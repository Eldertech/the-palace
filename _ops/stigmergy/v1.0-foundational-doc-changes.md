# STIGMERGY v1.0 — Foundational-Doc Changes (BBS Robustness Addendum)

The front-end is only as reliable as the conventions it reads. STATE renders frontmatter and markers; LOG parses commits; QUEUE reconciles against git and fires workers. If commits are ad-hoc, markers are prose, or board messages declare present state, the front-end degrades to a pretty but lying surface. These are the specific edits that make the foundational docs *produce* what the front-end needs.

Five robustness invariants drive every change below:

1. **Every commit is structured** — `kind(scope): summary` + `Palace-*` trailers, authored through `palace-commit`. This is what makes LOG legible and QUEUE reconciliation possible.
2. **Every board message is honest** — it asserts an act-at-a-time, names its `stale_if`, and points to live state; it never declares present truth.
3. **Markers are parseable, not prose** — the Active Handoff and stewardship-drift footers are structured so STATE reads them reliably.
4. **The repo is N-writer** — read-before-touch, re-read on "modified since read," never silent-overwrite, clear `.git/*.lock` before committing.
5. **Every dispatched worker honors the contract** — uses `palace-commit`, posts a completion/pickup message, respects the hard-coded audition gate.

---

## 0. Extract the Commit Specification as its own canonical doc

Right now the commit format lives inside the STIGMERGY v1.0 spec, and every ceremony stamps its own bespoke message. **Extract the commit specification into a single foundational entry** — `Commit Specification.md` (palace root, `type: meta`) — that CLAUDE.md, SCHEMA §5, the Substrate Skill, and every ceremony's Git step point to. One source of truth for kinds, trailers, and the `palace-commit` helper. This is the highest-leverage robustness change: without it, "every commit is structured" has no canonical home.

Add to `Palace Ceremonies.md` a **ceremony→commit-format table** (the single reference):

| Ceremony | Commit form | Key trailers |
|---|---|---|
| Deposit | `deposit(<Entry>): <summary>` | `Palace-Kind: deposit`, `Palace-Entry`(×n), `Palace-Verify` |
| Weave | `weave(<scope>): <N links, N promoted, N vectors>` | `Palace-Kind: weave`, `Palace-Campaign: weave-YYYY-MM-DD`, `Palace-Entry`(×n), `Palace-Stage`/`Palace-Vector` per change |
| Spore Check | `edit(<Entry>): spore-check — revived\|composted\|held` | `Palace-Kind: edit`, `Palace-Stage`, `Palace-Campaign: spore-check-YYYY-MM-DD` |
| Revival | `edit(<Entry>): revival — <reason>` | `Palace-Stage: <Entry>: dormant→<new>` |
| Walk | `edit(<Entry>): walk — <connection>` | `Palace-Kind: edit`, `Palace-Campaign: walk-YYYY-MM-DD` |
| Enrichment | `enrich(<Entry>): <desc>` | `Palace-Kind: enrich`, `Palace-Entry`, `Palace-Verify` |
| Handoff | `handoff(<Entry>): written\|consumed` | `Palace-Kind: handoff`, `Palace-Resolves` on consume |
| Self-Model | `edit(SUBSTRATE): self-model — <what>` | `Palace-Kind: edit` |
| Map Build | `ops(maps): map build — <scope>` | `Palace-Kind: ops` |
| Schema Ceremony | `schema(<doc>): <what> — v<version>` | `Palace-Kind: schema` |

## 1. CLAUDE.md (entry point)

- **Access Paths:** add STIGMERGY as a primary surface alongside Filesystem and GitHub — "STATE/QUEUE/LOG: the read, triage, and review front-end." Note it does not replace the Claude conversation, where ceremonies author.
- **New section — Commit Discipline:** all commits go through `palace-commit` (structured kind + trailers); never raw `git commit`. Obsidian/CLI commits are tolerated but annotated `ops`/`couldnt` by the hook. Point to [[Commit Specification]].
- **New section — Working Concurrently (N-writer):** the palace is mutated by multiple Claude sessions, the steward batch, and the enrichment worker at once. Codify: read before touch; if a file is "modified since read," re-read before editing; never silent-overwrite; clear `.git/HEAD.lock .git/index.lock` before committing if a prior session wedged them. (This promotes the two git-lock / modified-since-read auto-memories into canonical guidance.)
- **Ceremony Triggers table:** add a column or note for which ceremonies post proposals/handoffs to QUEUE (Weave, Handoff, Deposit-follow-ups, Walk).
- **In-File Comments section:** note that the structured Active Handoff and stewardship markers (below) are machine-read by STATE, so their format is now load-bearing.

## 2. SCHEMA.md

- **§5 Schema Change Protocol:** reconcile the bespoke `Schema Ceremony — [what] — v[version]` requirement with the commit spec. The schema commit is now `schema(<doc>): <what> — v<version>` + `Palace-Kind: schema`; the §5 failure-mode check (flag version increments whose commits lack the format) updates to check for the `schema` kind. Point §5 at [[Commit Specification]].
- **§8 Bundles:** add a sentence that the `[Entry] — [type]` filename convention is now parsed by STATE's navigator and LOG's per-entry history — the prefix discipline is robustness-critical, not only Obsidian-flat-namespace cosmetic.
- **Candidate Schema Ceremony (do deliberately, not casually):** canonicalize two **structured standing footers** so STATE renders them reliably instead of scraping prose:
  - `Active Handoff` → a structured block carrying the handoff path and its `handoff_ready` board-message id (so closing one closes the other).
  - `Stewardship marker` → a structured block disclosing "under active stewardship, may lag, live state here" with the steward id and last-consolidation pointer (per [[Drift and Consolidation]]).
  These are the only changes that touch required structure; everything else in this addendum is content/convention and needs no Schema Ceremony. The existing required fields (`title` matching filename, `type`, `pillars`, `stage`) already guarantee STATE can render any entry — no new required field is needed for basic rendering.

## 3. Substrate Skill (`_ops/Substrate Skill.md`)

- **Add the Commit Discipline** (palace-commit, kinds, trailers) — agents must use it.
- **Add the Honest-Board-Message discipline:** any message an agent writes to the board asserts an act-at-a-time, names `stale_if`, points to live state; never declares present state. (Generalizes the Path 2 health-stub self-disclosure already in the Infra Spec.)
- **Add the N-writer Concurrency Protocol** (same rules as CLAUDE.md, operational depth for agents): claim-before-work for dispatched workers, re-read on conflict, lock-clearing.
- **Add the Dispatched-Worker Contract:** every worker fired from QUEUE (a) commits via `palace-commit`, (b) posts a completion/pickup message (`handoff_picked_up` / a `WEAVE`/`PROOF`/`enrich` completion), (c) respects the hard-coded audition gate — never auto-ships sensory or irreversible work. This is what keeps the actuator safe.
- The stage-conditional steward posture already lives here; cross-link it to the worker contract.

## 4. Per-ceremony changes

**Deposit Ceremony** — Git step → `deposit(<Entry>): …` + trailers; batch deposits share a `Palace-Campaign`. The "flag existing entries for future Weave" notes should *optionally post to QUEUE as items* so follow-ups survive the session instead of living only in prose. Keep the Deposit Archive append.

**Weave Ceremony** (the big integration) — its **proposals** (new links, label enrichments, stage transitions, vector tunings) post to QUEUE as show-before-write items, so they survive the session and Loudon triages them in the digest rather than approving a wall of chat. Map Build precondition must emit `_ops/maps/palace-map-*.json` (STATE's Topology Lens reads it). Swarm workers' board messages must pass the §2.2 validator and the honest-message discipline. Commit → `weave(<scope>): …` + `Palace-Campaign`, with `Palace-Vector`/`Palace-Stage` per change.

**Enrichment Ceremony** (being absorbed) — rewrite the Infrastructure section: the standalone Flask server (`:7878`) is retired once Phase 4.5 lands; the card model, `card-validator` gate, and deposit/revise/discard loop live in STIGMERGY's QUEUE, driven by the ported `_fire_worker` actuator. Preserve the single-global-worker + PID-liveness + daemon-cleanup discipline (now in STIGMERGY's server). The `inbox.md` response channel becomes QUEUE actions. Commit form `enrich(<Entry>): …` is already closest to spec — just add trailers.

**Handoff Ceremony** — the `handoff_ready` board convention is already in § Announcing the Handoff on the Board. Add: commit `handoff(<Entry>): written|consumed`; consuming posts `Palace-Resolves: <handoff_ready id>` to close the QUEUE item; the Active Handoff footer becomes the structured marker (SCHEMA candidate above) carrying the board-message id, so STATE shows "active handoff" reliably to a board-bypasser opening the file.

**Spore Check / Revival** — structured commits with `Palace-Stage` trailers (so LOG renders stage changes field-level); dispositions optionally post to QUEUE.

**Walk Ceremony** — the "one unexpected connection" posts to QUEUE as a proposed link (show-before-write) so walks accrete proposals instead of evaporating; metadata-only commits use `edit(<Entry>): walk — …`.

**Map Build Ceremony** — the emitted JSON is now a **UI contract** (STATE's Topology Lens renders it); document the edge-list/node schema and keep the `palace-map-[scope]-YYYY-MM-DD.json` filename convention stable. Add a closed loop: a QUEUE "refresh map" action can fire Map Build via the actuator.

**Self-Model Update** — structured commit (`edit(SUBSTRATE): …`); note SUBSTRATE.md now also renders in STATE, and the self-model may read STATE's PULSE/topology data.

**Harvest Ceremony** — the "fast oblique card game" is literally a QUEUE card interaction; unify it: harvest candidates become QUEUE deposit-seed cards through the same card surface as Enrichment, so Harvest and Enrichment share one queue.

## 5. ROSETTA (minor)

Add the commit-kind vocabulary (`deposit/edit/enrich/handoff/steward/weave/schema/ops/merge`) as a cross-reference row, so the kinds are discoverable alongside the other vocabulary translations.

## Sequencing — what's a build prerequisite vs. a follow-up

- **Before the build can be trusted:** extract [[Commit Specification]] (§0) and add the Commit Discipline + N-writer protocol to CLAUDE.md and the Substrate Skill (§1, §3). The front-end is built against these; they should exist first.
- **Alongside the build:** the per-ceremony Git-step updates (§4) and the ceremony→commit-format table — these can land as the relevant ceremony is next run, or in one sweep.
- **Deliberate, on its own clock:** the Schema Ceremony for structured markers (§2) — it touches required structure, so it gets its own ceremony with rationale, not a casual edit.
- **After Phase 4.5:** the Enrichment Ceremony rewrite (§4) — only once the actuator and card loop actually live in STIGMERGY, so the doc never points at a retired server prematurely.

Each change above is small on its own; together they make the BBS a surface the front-end can trust — because what it reads (commits, markers, messages) is produced in a shape it can rely on.
