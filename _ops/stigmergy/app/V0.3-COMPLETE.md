## What v0.3 is

The first deliberate **lab → integration** crossing. The rendering capability
proven in `Enrichment/server.py` now lives in STIGMERGY: image, audio, and
sandboxed-HTML artifacts render **inline inside a message**, served by a new
path-safe `GET /api/file` endpoint and keyed on a payload convention. The
Enrichment server stays the lab; STIGMERGY absorbed the rendering only — no
data-model unification, no `claude -p` worker change, no §2.2 / SCHEMA edit.

## What v0.3 is not

Not a data-model merge with the Enrichment lab, not a response-vocabulary
migration (enrichment cards are `BROADCAST`s, so they never enter the Trickster
inbox flow), not a deck view (`payload.deck_id` grouping is deferred), not a
phosphor audio control strip (browser-default `<audio>` is the accepted v0.3
break), not a Steward change.

## New endpoint + features (v0.3)

- **`GET /api/file?path=<palace-relative>`** — streams a palace file with
  content-type detection (table mirrors `Enrichment/server.py:_guess_type`),
  `Content-Length`, `Cache-Control: no-cache`. Resolved through the existing
  `resolveInsidePalace` guard: `400` on missing/empty/traversal/absolute/
  directory; `404` on nonexistent. Read-side counterpart to the strict
  write-side validator — lenient about *what*, strict about *where*.
- **Inline artifact slot** — any message type renders its artifact(s) inline
  when `payload.artifact_path` (string) or `payload.artifacts: [{path,
  caption?}]` is present. image → `<img>`; audio → `<audio controls>`; html →
  `<iframe sandbox="allow-scripts">` (no `allow-same-origin`); other → an
  `↗ open` link via `/api/open`. Keyed on artifact *presence*, not message
  type or `kind`.
- **`enrichment` tag** — shown beside the message type when
  `payload.kind === "enrichment_card"`. `from:` is the target page's title
  (page-as-agent identity), not an invented handle.
- **Round-trip proof** — `tests/e2e/rich-content-roundtrip.spec.js` POSTs an
  enrichment-shaped message to the **real** persistent board (proving the
  `kind` discriminator + artifact fields pass the **untouched** §2.2 validator
  — `payload` is opaque by spec), reloads, renders the artifact inline, and
  restores the board so it leaves no trace.

## Decisions Loudon should review

### 1. The live persistent board has a Steward backlog (real signal — please look)

This is the most important note. While running the full-regression gate I found
the live persistent blackboard (`_ops/swarm/persistent/blackboard.jsonl`, 152
lines) now carries **45 `RESOURCE_REQUEST`s and only 30 responses** — roughly
**15 unanswered Steward requests** (gsl-steward, gwl-steward, shepard-steward,
slime-mold-delay, semantic-delay, …) dated 2026-05-27. These are real pending
Trickster decisions awaiting you — open STIGMERGY on TRICKSTER (no `?demo`) to
triage them. v0.3 did not create these; it surfaced them.

### 2. I made the v0.2 inbox/click-to-respond e2e tests hermetic

Those Steward requests broke 7 v0.2 e2e tests in `inbox.spec.js` /
`click-to-respond.spec.js` — **not a v0.3 regression** (my diff never touches
`TricksterInbox.jsx`, the inbox sort, the demo resource-requests, or the live
board). The tests encoded a stale assumption from the v0.2 era — *"the real
palace persistent has no TRICKSTER-board RESOURCE_REQUESTs"* — which is no
longer true. Two distinct drift effects:

- Steward requests carry `payload.options[]`, so they render the `InlineResponse`
  form (`inline-response-options` + SEND), **not** the canonical modal-driven
  `inbox-response-options` block the tests target; and they sort newest-first
  above the demo request.
- The confirm tests POST a `RESOURCE_GRANT` to the live board; their cleanup
  helper (`clearDemoSession`) had a long-standing path bug (it resolved
  *four* levels up, landing **outside** the palace), so it never cleaned
  anything and orphan GRANTs accumulated.

Following the exact pattern the v0.2 build itself used for `data.spec.js` /
`health.spec.js` ("switched to hermetic data"), I made these deterministic:

- Added two **additive** demo modes in `App.jsx` — `?demo=only` (demo data
  alone, no live board) and `?demo=empty` (no data). `?demo=1` and the default
  (live-only) behavior are unchanged.
- Retargeted the affected tests to `?demo=only` (deterministic single pending
  item → canonical `inbox-response-options`) and `?demo=empty` (genuine
  empty-state / no-pending assertions).
- Replaced the broken `clearDemoSession` with a real **snapshot/restore of the
  persistent board** (`beforeAll` snapshot, `afterEach` restore), so the
  confirm tests now leave **zero** trace on the live board (strictly better
  than v0.2, which polluted it).

**Review question:** is a hermetic, demo-only fixture the right long-term home
for the inbox suite, or do you want it to keep exercising the live board (in
which case it needs you to keep the Steward backlog answered)? My call was
hermetic, because a regression suite should test UI behavior deterministically,
not the day's palace state.

### 3. iframe sandbox is `allow-scripts` only

Deliberately **not** `allow-same-origin` (the handoff's decision). Served HTML
loads from STIGMERGY's own origin, so withholding same-origin forces it into an
opaque origin: scripts run, but it cannot read the BBS DOM/storage or POST to
the orchestrator endpoint. The "Two Phasors" sim renders fine under this. If a
real palace artifact ever needs `allow-same-origin` to render at all, that is a
documented stop condition (it would mean the convergence tension surfacing as a
concrete fact) — none did during this build.

### 4. Gate numbering

v0.3's three phases reuse `check-phase.js` integer keys `7` / `8` / `9` (npm:
`check:phase-7/8/9`) so v0.2's phases 1–6 don't renumber. `check:all` now loops
1→9. Screenshots live under `screenshots/phase-{8,9}-v0.3/`.

## Findings flagged for v0.4+

- **Phosphor-styled audio control strip** — browser-default `<audio>` is the
  v0.3 break.
- **Deck grouping** (`payload.deck_id`) and a `?deck=` board filter — the
  lingering-vs-breadth UX question, downstream of rendering.
- **Cross-origin `postMessage`** from sandboxed artifacts (facets that respond
  from inside the artifact) — real engineering, no current artifact needs it.
- **Inline text/markdown artifacts** (`<pre>`) — v0.3 falls back to an open-link
  for non image/audio/html types.
- **Response-vocabulary migration** from the Enrichment lab (tap-a-label,
  free-prose textarea per card) — a separate later move.
- **Steward enrichment payloads** — no Steward currently emits `artifact_path`;
  they still hand-link via `obsidian://` / `open:`. v0.3 makes the inline path
  available; adopting it is a Steward-side change.

## Post-completion follow-up (2026-05-29)

After the smoke-test, Loudon asked that every board show the **latest message at
the top**. Investigation found a real bug: all three sort sites
(`MessageList`, `roster`, `inbox`) compared `ts` **lexically**, which disagrees
with chronological order once timestamps mix timezone offsets — and the live
board carries both `...Z` and `...-04:00` stamps, so the genuinely-newest
message did not always land on top.

- Added `tsToEpoch` / `tsCompare` to `format.js` — parse-to-epoch comparison,
  timezone-safe, `-Infinity` for missing/unparseable (sinks to the bottom).
- `MessageList` (all channel boards) and `AgentRoster` now sort **chronological
  newest-first**.
- **Inbox order flipped** from oldest-first ("longest waiting") to **newest-first**,
  for consistency with "latest at top on every board." *Review question:* if you
  prefer the Trickster inbox to keep surfacing the longest-waiting request first
  (a triage convention), say so and I'll revert just the inbox direction — the
  chronological-correctness fix stays either way.
- Added `data-ts` on message rows, comparator unit tests (incl. a mixed-timezone
  case), and `tests/e2e/ordering.spec.js` asserting every board renders
  newest-first chronologically. Gate re-run green.
