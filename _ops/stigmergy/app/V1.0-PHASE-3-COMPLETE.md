## What Phase 3 is

The machinery that makes every commit structured, so the LOG deck stays legible and QUEUE reconciliation (Phase 6) becomes possible. Three parts, one shared pure library:

- **`src/lib/commit-spec.js`** (pure, 28 unit tests):
  - `validateCommitMessage(text)` → `{ valid, errors, warnings, parsed }`. The hook's brain.
  - `annotateOutOfBand(text, {author})` → appends `Palace-Kind: ops`, `Palace-Verify: couldnt`, `Palace-Author`, `Palace-Annotated: commit-msg-hook` to a non-spec message. Idempotent; only ever ADDS lines.
  - `deriveTrailers({paths, mdChanges, kind, verify, ...})` → the trailers the author shouldn't type: `Palace-Entry` per touched `.md`, `Palace-Stage` + `Palace-Vector` from the frontmatter diff, plus campaign/resolves/author. Includes Revision 2's `mixed` kind and `Palace-Campaign`.
  - `formatCommitMessage(...)` → assembles the message; round-trips back through the validator.
- **`scripts/palace-commit.mjs`** (integration-tested against real temp repos) — the single structured producer. Stages **explicitly-named paths** (never `git add -A` — the hard Phase 2 lesson), reads the staged diff, derives trailers, commits a conformant message. Clears stale `.git/*.lock` first (the Cowork sharp edge). `--dry-run` prints without committing.
- **`scripts/commit-msg-hook.mjs`** + **`scripts/install-hooks.mjs`** — the tolerant backstop. The hook validates every commit; a conformant message passes through untouched, an out-of-band one (Obsidian/CLI) is **annotated in place, never rejected**. It exits 0 even on internal error — it must never wedge Loudon's commit. The installer writes a self-locating POSIX shim into `.git/hooks/commit-msg`, backing up any prior hook, with `--check` / `--uninstall`.

## The gate, proven

- **New commits validate.** `buildMessageFromStaged` → `validateCommitMessage` round-trips green; the CLI commits a structured message end-to-end in a temp repo (`edit(Foo): grow` with derived `Palace-Stage: Foo: seed->sprout`, `Palace-Vector`, `Palace-Entry`).
- **Out-of-band commits annotate, not block.** With the hook installed in a real temp repo, `git commit -m "just did a thing"` is recorded as `just did a thing` + `Palace-Kind: ops` + `Palace-Verify: couldnt`. A conformant commit is recorded unchanged (no `Palace-Annotated`).
- **N-writer safety.** The CLI test stages only `--path Foo.md` while an unrelated dirty `Other Session.md` sits in the tree, and asserts the unrelated file is NOT committed. (This phase was itself built while a concurrent Shop session committed — the explicit-path discipline held.)

## Two decisions for Loudon (NOT done yet, deliberately)

Phase 3 code is complete and isolated. Two things it does NOT do, because both touch shared/canonical surface and deserve your call:

1. **The canonical docs are drafted, not committed.** The foundational-doc addendum (`_ops/stigmergy/v1.0-foundational-doc-changes.md`) §0/§1/§3 calls for a new `Commit Specification.md` (palace root, `type: meta`) plus additions to `CLAUDE.md` (Commit Discipline + N-writer protocol) and the Substrate Skill. These are palace **canon** — "show before writing" applies. I'll present drafts in the conversation for approval before they're written.
2. **The commit-msg hook is built but NOT installed.** A `commit-msg` hook is **repo-global** — it fires on every commit by every concurrent session and by your Obsidian/CLI. Installing it silently would be exactly the cross-session interference Phase 2 taught caution about. Installation is one deliberate command for you to run when traffic is quiet:
   ```
   node _ops/stigmergy/app/scripts/install-hooks.mjs
   ```
   It is tolerant-by-design (annotates, never blocks), so it is safe — but it's still your switch to throw.
