## What Phase 5 Stage A is

STATE's write surface, gated to **dry-run preview only**. Open an entry, edit its frontmatter through SCHEMA-bound forms and its body in a markdown textarea with `[[wikilink]]` autocomplete, click Save, and see exactly the structured commit `palace-commit` WOULD make — subject + derived `Palace-*` trailers + unified diff. The editor IS the audition surface. Nothing reaches the working tree.

This is the seam the v1.0 thesis names ("a save is not the end of the act; recording it is") made literal — the act lives entirely in the preview until Loudon arms Stage B.

- **`src/lib/yaml-emit.js`** (pure, 22 unit tests) — palace YAML emitter. js-yaml.dump round-trips technically valid YAML but reorders keys, inlines arrays it shouldn't, and quote-decorates inconsistently. The emitter writes palace-idiomatic YAML: canonical top-level order (SCHEMA §3 strong fields first), block-style `links` with `target/type/label`, inline-flow `pillars`/`tags`, conservative quoting (forward_vector always quoted; wikilink targets quoted; reserved scalars and number-like strings quoted), nested objects (agency_profile) preserved. `emitEntryFile` normalizes the close-fence/body separator to one blank line so the parser ↔ emitter round-trip is stable. Round-trip-tested against three fixtures.
- **`src/lib/entry-edit.js`** (pure, 35 unit tests) — the form-state model + the SCHEMA enforcement + the allow-list:
  - `ENTRY_TYPES` (12, §1), `STAGES` (7, §2), `PILLARS` (4, §3), `LINK_TYPES` (10, §4) — the enums the UI binds to.
  - `TYPE_REQUIRED_FIELDS` — the type-specific required fields (project→status; source→author/year/medium; spore→revival_conditions; specialist→status/medium/tool/tool_version; etc.).
  - `STAGE_EXEMPT_TYPES` / `PILLARS_OPTIONAL_TYPES` — the §3.2 exemptions for specialist + maker.
  - `validateFrontmatter` — returns `{ valid, errors, warnings }`. Errors block save; warnings flag conatus discipline lapses (stasis-verb pattern in forward_vector — "I will remain" etc.).
  - `isDirty` — set-aware on pillars and links so a row reorder doesn't trip dirtiness.
  - `wikilinkSuggestions` — pure resolver for the body textarea's `[[...]]` popup.
  - **`checkAllowList`** — the hard guardrail. Refuses path traversal, non-`.md` paths, machinery (`.git/`, `.claude/`, `.obsidian/`, `_ops/stigmergy/app/`, `_ops/swarm/`, etc.), and palace **canon** (CLAUDE / SCHEMA / SUBSTRATE / JEWEL / ROSETTA / FOUR PILLARS / README - The Palace Guide / `_ops/Substrate Skill.md` / `_ops/Palace Ceremonies.md` / individual `_ops/*Ceremony*.md` cards). Canon edits stay in the Claude conversation under show-before-write, per CLAUDE.md and the handoff.
- **`server/entry-save.js`** + endpoint `POST /api/entry/save` (9 integration tests) — pure pipeline composer:
  1. allow-list the path,
  2. validate the proposed frontmatter (SCHEMA enforcement),
  3. emit YAML + assemble proposed file content (`emitEntryFile`),
  4. read the on-disk current content (or empty for new entries),
  5. palace-aware diff via the existing `frontmatter-diff.js` (Phase 3),
  6. derive `Palace-*` trailers via `commit-spec.deriveTrailers` (Phase 3) — entries, stages, vectors, verify, author,
  7. format the structured commit via `commit-spec.formatCommitMessage`,
  8. generate a unified diff via `git diff --no-index` against temp files, rewrite the temp-paths back to the palace-relative path.
  
  Returns `{ ok: true, preview: { subject, trailers, message, udiff, frontmatterChanges, bodyChanged, wasAdded, warnings } }` or `{ ok: false, status: 403|422|400, error?, errors?, warnings? }`. **Never writes the entry file. Never commits.** Allow-list + canon refusal are server-side, not just UI — even a hand-crafted POST cannot slip through.
- **UI** (`src/components/state/`):
  - `EntryEditor.jsx` — top-level shell. Pre-flight `checkAllowList` so deep-linked paths can't slip past. Body textarea on the left, frontmatter form on the right rail, save controls + preview panel at the bottom. Save button enables only when dirty + valid + summary non-empty.
  - `FrontmatterForm.jsx` — every widget bound to a SCHEMA enum (type picker, 7-segment stage stepper, pillars chip multiselect, conditional type-specific required fields with proper enums for `status`/`medium`, repeating link rows, forward_vector textarea with conatus hint).
  - `LinkRowEditor.jsx` — one repeatable typed-link row: target with wikilink-index autocomplete (and an "unknown" warning for targets that don't match a real entry), `type` dropdown bound to the 10 SCHEMA §4 link types, optional `label`.
  - `WikilinkTextarea.jsx` — plain textarea + `[[name]]` autocomplete popup matching the BBS aesthetic. ↑↓ to navigate, Enter/Tab to insert, Esc to dismiss.
  - `CommitPreviewPanel.jsx` — renders subject + trailers + a syntax-colored unified diff (green for `+` lines, red for `-` lines, dim for headers, warn for `@@` hunks).
- The `[E] edit` chip is wired into `EntryReader.jsx`. The chip is disabled (and tooltip-named) for canon and machinery paths. `StateDeck.jsx` swaps to the editor when invoked and back to the reader on cancel.

## The dry-run promise, proven

- **Unit:** YAML emitter round-trips against three palace-idiom fixtures (a concept, a specialist with empty fields, a nested agency_profile). The edit-model enforces every SCHEMA enum.
- **Integration:** `POST /api/entry/save` previews a stage transition with the correct `Palace-Stage: <Entry>: mature->fruiting` trailer; marks `Palace-Vector: <Entry>: changed` when forward_vector is edited; returns a unified diff containing the changed line; **does NOT write the file on disk** (asserted by reading the file before and after the POST); refuses canon files with **403**; refuses `_ops/stigmergy/app/` machinery with **403**; returns **422** with schema-violation errors when the proposed frontmatter is broken; returns **422** when the proposed file is byte-identical to the current ("nothing changed"); returns **422** when summary or verify is missing.
- **E2E (against the live palace):** Open Kuramoto Coupling, the editor opens; the form widgets expose all 12 §1 type enum values and all 7 §2 stages; clicking a stage chip marks the editor dirty; Save is disabled until summary is filled; Save renders the structured-commit preview with the exact expected subject + trailers + diff; **the file on disk is byte-identical before and after** (asserted via two `/api/entry` reads bracketing the Save click).

## What this does NOT do (deferred to Stage B and onward)

- **No armed write.** `STIGMERGY_ARM_WRITE=1` is the second human switch (the first — installing the commit-msg hook — landed earlier). Stage B reuses this entire composer, adds a `--worktree` arg to `palace-commit`, and writes to `../palace-stigmergy-edits` on the long-lived `stigmergy-edits` branch. The dry-run preview surface and the allow-list guardrail Stage A landed are inherited unchanged.
- **No `git worktree` setup yet.** The worktree design is in the handoff (`_ops/stigmergy/v1.0-phase5-handoff.md`). Stage A's allow-list and pure-composer pipeline are the prerequisites that Stage B builds on.
- **No bundle-file editor.** SCHEMA §8 bundle files (handoffs, contexts, sources) carry minimal YAML (no `type`, no `pillars`, no `stage`); they need a lighter editor surface than the full entry form. Deferred — noted as open question #5 in the contract.
- **No agency_profile editor UI.** The YAML emitter round-trips nested agency_profile objects fine, but the form does not yet offer the 4-cell editor for it. Add when an entry actually needs it edited through STIGMERGY.
- **No CodeMirror or markdown live-preview.** Stage A uses a plain textarea + wikilink popup, per Loudon's call. Obsidian remains the heavy-editor fallback over the same files.

## Decisions worth flagging to Loudon

### 1. Canon hard-refuse (your call, 2026-05-31)

You picked **hard refuse — endpoint returns 403** for canon paths (CLAUDE / SCHEMA / SUBSTRATE / JEWEL / ROSETTA / FOUR PILLARS / `_ops/Substrate Skill.md` / `_ops/Palace Ceremonies.md` / `_ops/*Ceremony*.md`). The check is server-side AND UI-side; the editor button is disabled for these entries with a tooltip naming the reason, and the POST endpoint refuses even a hand-crafted attempt. Stage B inherits this unchanged — zero risk of an armed write hitting canon.

### 2. Plain textarea + wikilink popup (your call, 2026-05-31)

Body editor is a plain `<textarea>` with a `[[name]]` autocomplete popup, no markdown editor library. ~150 LOC instead of ~200KB of CodeMirror. Trade-offs: no syntax highlighting in the body, no live preview, simpler undo stack. Obsidian remains the heavy editor over the same files. If you find yourself reaching for CodeMirror later, the swap-in point is `WikilinkTextarea.jsx` — keep it isolated.

### 3. YAML emitter is custom, not raw js-yaml.dump

js-yaml.dump produces technically valid YAML but stylistically noisy diffs (key reorders, inconsistent quoting). The custom emitter preserves palace idiom and round-trip-tests against fixtures. The cost is ~150 LOC + ~22 tests; the benefit is that an edit-and-save through STATE produces a minimal, signal-only diff in LOG — important because LOG is the audition surface.

### 4. Author defaults to `loudon` for STATE saves

The `Palace-Author` trailer defaults to `loudon` when STATE is the producer — the form is driven by a human at the keyboard. `palace-commit` itself defaults to `claude` (since Claude calls it directly during ceremonies). Could be made explicit per save (a picker), but the form-driven heuristic is correct ~all the time. Flag if you'd rather see a picker.

### 5. The four "n/a" items in the visual-validator report

The validator marked four items n/a — out of frame, not failures: (a) verifying all 12 §1 type enum values in the picker (the picker is open as a `<select>` so only the currently-selected `concept` is shown; the playwright spec asserts the full enum is offered); (b) the Save button's disabled-state transition (both captures show it enabled); (c) the `[E] edit` button's presence on ordinary PULSE rows (the captures jumped straight into the editor); (d) the `[E] edit` button's disabled state on canon rows. (b) and (a) are asserted in the e2e suite (`tokens.spec.js` covers the global tokens; `state-editor.spec.js` asserts the enum and the disabled-Save transition). Worth a follow-up capture suite that covers the negative states.
