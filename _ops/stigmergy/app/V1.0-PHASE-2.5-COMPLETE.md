## The keystone, in one line

The board stops being a pheromone field and becomes an **actuator**: a QUEUE action now fires a headless `claude -p` worker. The mechanism [[Two Batons, One Board]] said the board lacked. STIGMERGY's Node server inherits the Enrichment `_fire_worker` pattern — **carry the lessons, not the language** (Python/Flask → Node `child_process.spawn`), with every robustness scar preserved.

## Backend decision (resolved, per the handoff)

**Re-implemented `_fire_worker` in Node; no Python sidecar.** The Flask app (`Enrichment/server.py`) is superseded, not deleted — it retires in Phase 4.5 when the card loop also moves over (the handoff sequences the retirement there). One backend owns the worker-fire.

## The four scars, carried exactly

1. **`bypassPermissions` is load-bearing.** Default argv `['claude','-p',prompt,'--permission-mode','bypassPermissions']`. Headless `claude -p` has no TTY for Write/Edit prompts; without it the worker hangs. The flag doubles as the liveness signature (scar #2).
2. **Existence != liveness.** `pidIsOurWorker(pid)` runs `ps -p <pid> -o command=` and requires the `bypassPermissions` signature. A bare `kill(pid,0)` reports a recycled pid as alive; the `ps` check rejects it. Verified by a test that points the pid file at this live (non-worker) test process and asserts `isAlive()` is false + cleans the stale file.
3. **Exit cleanup.** `child.on('exit')` removes `.worker.pid` (only if it still names that pid — avoids racing a newer fire). Across restarts the `ps`-liveness check heals stale state. Verified: fire a stub, wait, assert the pid file is reaped.
4. **Single global worker per lane.** A second fire while one is alive is refused — verified at the actuator layer and the HTTP layer (409 Conflict).

## Proven without ever firing a real agent

The mechanism spawns autonomous workers, so the test path **never** fires real `claude`:
- **Injectable `buildArgv`.** Tests fire a harmless `tests/fixtures/stub-worker.mjs` (a node sleep script) that *still carries the `bypassPermissions` signature*, so the ps-liveness scar runs for real against a genuinely ours-shaped but harmless process.
- **Server stub gate.** `STIGMERGY_STUB_WORKER=1` makes the dev server fire the stub; `GET /api/worker` reports `stubbed: true`. The fire-through e2e and the `actuator-fired` capture **hard-gate on `stubbed`** — they refuse to run against a real-worker server, so a misconfigured run can never spawn `claude`.

## The visible surface (minimal, by design)

`ActuatorPanel` atop the QUEUE deck: status line (`○ idle` / `● WORKER ALIVE` amber + pid / `last fire: ok|failed`), a guarded prompt + `[F] FIRE` (disabled while alive), a streaming log tail. Phase 4.5 wires real enrichment-card actions through this same actuator.

## Endpoints

- `GET /api/worker` — status (running / pid / started / logTail / lastFire / `stubbed`). Read-only; polled every 2s.
- `POST /api/worker/fire` — body `{ prompt }`. `409` when one is alive; `400` on empty prompt; `200` + status on success.

## N-writer reality (the hard lesson, now codified in practice)

A concurrent "Shop" build session shared this one working directory through most of this phase and repeatedly overwrote uncommitted files (and, in an earlier `git add -A`, a Phase 2 commit swept its philosophy deposits). **A separate git branch is NOT isolation when the working directory is shared** — a concurrent session commits to whatever branch is checked out and clobbers your uncommitted edits. The practical guards adopted, now permanent for this build:
- **Never `git add -A`** — stage only explicit paths.
- **Commit each phase the moment its gate is green** — don't let working-tree edits sit while another writer is active.
- A true fix is a separate `git worktree` per session (noted for Loudon). The Shop session is now done, so the directory is single-writer again.

This is exactly the failure mode Phase 6's reconciliation engine must make first-class.
