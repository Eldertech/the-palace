## What Phase 2 is

The retrospective deck — a git explorer, honest by construction:
- **Read-only git adapter** (`server/git.js`) — spawns `git` with argument arrays (no shell), validates pathspecs/refs against injection. `GET /api/log` (stream, `?path=` per-entry, `?limit=`), `GET /api/commit?sha=` (palace-aware diff), `GET /api/uncommitted` (working-tree delta).
- **Commit classification** (`src/lib/commit-parse.js`) — parses `kind(scope): summary` + the `Palace-*` trailer block; infers kind from touched paths for pre-spec commits, flagging provenance (`trailer`/`subject`/`inferred`). Enum = spec's nine + `mixed`.
- **Raw-git parsers** (`src/lib/git-log-parse.js`) — pure, delimiter-robust (`%x1f`/`%x1e`), with C-style path dequoting so real palace paths with spaces/commas/non-ASCII parse.
- **Palace-aware diff** (`src/lib/frontmatter-diff.js`) — frontmatter field-level (`stage: a->b`, `+N links`, `forward_vector changed`), links/pillars as sets, body as a flag, media additions flagged for inline render.
- **Filtering** (`src/lib/log-filter.js`) — kind/author/pillar(joined against the catalog)/entry/text/time + campaign-thread grouping.
- **UI** — `LogDeck`, `CommitCard`, `CommitDiff`, `UncommittedBanner`, `LogFilters`.

The Phase 1 LOG stub is removed.

## Bugs found + fixed during the build

1. **Git C-style path quoting.** `git log --numstat` and `git status --porcelain` wrap spaced/comma/non-ASCII paths in double quotes — so `"Palace development/Two Batons, One Board.md"` would never match an entry. Added `dequotePath()` (handles `\"` `\\` `\t` `\n` `\r` + octal UTF-8 byte escapes), applied at both the numstat and porcelain path sites. Without it, per-entry filtering misses most of the palace. Covered by deterministic unit tests (quoted spaced path + octal UTF-8).
2. **`git status --porcelain` rejects `--no-color`.** It errored; `allowFail` swallowed it; the tree always read clean (banner never fired). Removed the flag.
3. **Root-commit diff.** `git show <root>^:<path>` has no parent; handled via `allowFail` so a first-commit add reports `wasAdded` instead of crashing.
4. **Flaky uncommitted test.** The `/api/uncommitted` dirty-tree test shared a `beforeAll` repo with the clean-tree test and flaked under full-gate concurrency. Fixed with per-test repos (`beforeEach`/`afterEach`).

## Decisions Loudon should review

1. **Pre-spec kind inference is heuristic, labeled with `?`.** ~58/60 recent commits predate the spec; kind is inferred from paths and rendered dim with `?`. Once Phase 3's `palace-commit` is the producer, new commits carry real trailers and the `?` drops. Review: reasonable inference table, or show a neutral `other`?
2. **Pillar filter fetches the entries catalog** once on LOG mount (pillar lives in entry frontmatter, not the commit). Chips disabled until it resolves. Acceptable?
3. **200-commit default window.** Full history browseable via `?limit`; no pagination UI yet (a named Open Question / stop-condition — it did *not* trip; the explorer stays responsive at current depth).
4. **Body diff is a flag, not a prose diff.** Field-level frontmatter is the high-signal part (stage moves, vector changes, link counts — auditable at a glance). A terminal-native prose diff is a clean later addition.
