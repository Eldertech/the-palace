## What Phase 1 is

The retro/prospective discipline made navigational. Three top-level decks (STATE / QUEUE / LOG = present / future / past) wired as the literal shape of the screen, with STATE — the read surface — fully built:

- **Recursive entry catalog** (`/api/entries`) walking the live palace (~400 `.md` files), parsing each frontmatter with `js-yaml`, surfacing bundle and Active-Handoff signals on each summary.
- **PULSE vitality lens** — entries sorted by a small score combining `last_activated` recency, `activation_count` magnitude, stage weight, and has-handoff / has-stewardship-marker bumps. The score is rendered as a 5-position ASCII dot meter (`* . . . .`) on each row.
- **Entry reader** — YAML-as-header (`FrontmatterHeader`), body wikilinks resolved against the live index (`EntryBody`), typed-link panel (`TypedLinkPanel`) showing the semantic web separate from the conversational fabric per SCHEMA §4, bundle navigator (`BundlePanel`) showing the entry WITH its owned files per SCHEMA §8.
- **Inline enrichment rendering** — the v0.3 `ArtifactSlot` pointed at entry bundles: images via `<img>`, audio via `<audio controls>`, html via sandboxed iframes, video via `<video controls>`. The "enrichment renders where it lives" promise of the v1.0 thesis is kept by reusing the existing engine, not by building a parallel one.
- **Bundle-aware navigator** — `Foo.md` ↔ `Foo/` are shown as one owned unit per SCHEMA §8. Hidden files (`.DS_Store`, `__pycache__/`, `Archive/`) are excluded.
- **Three-deck shell** — `DeckTabs` with `[S]TATE [Q]UEUE [L]OG` hotkeys; deck subtitles `PRESENT -- WHAT IS / FUTURE -- WHAT IS WAITING / PAST -- WHAT HAPPENED` (palace standing rule: no em dashes).
- **QUEUE shim** preserves the entire existing v0.4 board view inside the new deck (Phase 4 will reframe).
- **LOG stub** announces Phase 2 explicitly so the chrome is honest about what does and doesn't work yet.

## Decisions Loudon should review

### 1. Added one dependency: `js-yaml`

The Python `parse_frontmatter` in `Enrichment/server.py` is a flat-only YAML scanner. STATE has to read palace frontmatter that uses nested arrays-of-objects (`links: [{target, type, label}]`), nested object hashes (`agency_profile: {creation, tools, ...}`), and quoted scalars — none of which a hand-rolled parser handles cleanly. Misparsing user data is a worse failure than a single 30KB dep, so I added `js-yaml@^4.1.1`. It's the only new dependency in Phase 1; the rest is React + Vite as before.

**Review question:** Acceptable? Or would you rather a hand-rolled parser specific to palace YAML conventions, even if it costs round-trip fidelity on edge cases (multi-line strings, escapes, complex objects)?

### 2. Phase numbering extends the existing integer keys (11..19)

`check-phase.js` already uses keys `1..10` for v0.2 / v0.3 / v0.4 phases. v1.0's nine phases get keys `11..19` so the existing keys don't shift. Checklist files are named `phase-N-v1.0.md`; screenshot dirs are `phase-N-v1.0/`. The `check:all` script now runs `1..11`.

**Why this matters later:** Phase 2 = `check-phase.js 12`, Phase 2.5 = `13`, etc. If you'd prefer a separate v1.0-namespaced script (`check:v1.0-phase-1`), say so before Phase 2.

### 3. Default deck is STATE; existing tests that need QUEUE got a one-line patch

The contract says the present (STATE) loads first. To keep all 50+ existing v0.x e2e tests green without per-test refactors, I added a backward-compat heuristic: **when `?demo=` is in the URL, default the deck to QUEUE.** All existing tests use `?demo=1` / `?demo=only` / `?demo=empty`, so they land on the board view as before without modification. Five tests that used plain `/` and asserted board-only chrome were patched:

- `boot.spec.js` — now asserts both decks reachable (STATE default, QUEUE via `q` hotkey).
- `tokens.spec.js` — global tokens; waits for `deck-tabs` instead of `board-screen`.
- `tabs.spec.js` empty-state test — explicitly `?deck=QUEUE`.
- `rich-content-roundtrip.spec.js` — explicitly `?deck=QUEUE`.
- `_capture.spec.js` phase-2 capture — explicitly `?deck=QUEUE`.

A new query param `?deck=STATE|QUEUE|LOG` lets any test (and a future Phase 6 deep-link feature) land directly on a specific deck.

### 4. The PULSE score is a first cut

The vitality lens uses: recency (0.4 weight) × activation_count (0.3) × stage weight (0.3) + handoff bump (+0.25) + stewardship bump (+0.15). Foundational entries (CLAUDE, SCHEMA) currently sit mid-list rather than at the very top — they're foundational *and* infrequently re-activated. That feels right to me (PULSE answers "what's hot right now"), but if you want foundational metas to sticky-pin, name it and I'll add a small post-sort lift.

**Spotted in the index:** four entries surface a `[handoff]` marker — your handoffs found are alive. The build's own contract (STIGMERGY v1.0 — Palace Front-End) shows up first because it carries the freshest handoff.

### 5. Entries indexer excludes machinery, includes knowledge

`_ops/stigmergy/app/`, `_ops/stigmergy/orchestrator/`, `_ops/stigmergy/trickster-auto/`, `_ops/swarm/`, `Enrichment/card-NNN/`, `Enrichment/Archive/`, `node_modules`, `dist`, `screenshots`, `playwright-report` are all excluded. **Everything else under `_ops/` IS indexed** — including `_ops/Substrate Skill.md`, the build handoffs, the foundational-doc changes. The palace's knowledge entries can live anywhere under root (CLAUDE.md is explicit about this).
