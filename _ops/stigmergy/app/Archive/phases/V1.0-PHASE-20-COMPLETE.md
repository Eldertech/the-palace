## What Phase 20 is

The LOG deck stops merely *surfacing* the working-tree delta and starts *acting*.
Its uncommitted banner (already the "invisible-dive hazard made visible") becomes
a **structured commit composer**: tick the files you want, write a palace-spec
message, and record them — without leaving the BBS.

The deliberate v1.0 line ("v1.0 surfaces; it does not act") is crossed here, on
purpose, reusing the commit machinery that already existed: `commit-spec.js`'s
`deriveTrailers`/`formatCommitMessage` (pure) derive the Palace-* trailers from
the staged diff, so the author types only kind / scope / summary / Palace-Verify.

## How it works

- `POST /api/commit/create { paths, kind, summary, verify, scope?, body? }`
  (`server/commit.js`): validates against `KNOWN_KINDS` / `VERIFY_VALUES` /
  `safePathspec`, clears stale Cowork git locks, **stages ONLY the named paths
  (never `git add -A`)**, derives trailers from the selected staged diff, and
  commits **exactly those pathspecs** (`git commit -F msg -- <paths>`) so a
  foreign pre-staged file is never swept in. Stamped `Palace-Author: loudon`.
- The banner (`UncommittedBanner.jsx`) makes each file a checkbox, adds the
  composer (kind/scope/verify selects + summary/body inputs), and a RECORD
  button gated on `≥1 file selected && summary non-empty`. On success it clears
  and reloads the LOG.

## Safety / hygiene

- Carries the two `palace-commit.mjs` lessons: **never `git add -A`** (the
  N-writer repo must not sweep another session's work) and clear stale git
  locks first. Selecting one workstream commits only that workstream.
- The integration test proves the consequential property against a throwaway
  git repo: committing `data.txt` leaves a sibling `README.md` edit
  **uncommitted** (not swept), and the message carries the derived
  `Palace-Kind`/`Palace-Verify`/`Palace-Author` trailers. Plus 400s for unknown
  kind, bad verify, no selection, empty summary, and path traversal.
- The e2e is read-only — it verifies the indicator + RECORD gating and NEVER
  clicks RECORD (which would make a real commit). The stage→commit path is the
  integration test's job.

## Endpoints added

- `POST /api/commit/create` — stage the selected paths + commit a spec-conformant
  message; 400 on validation failure, 200 with `{ shortHash, subject, committed }`.
