## The standing discipline (carry forward)

1. **NEVER `git add -A`.** Stage only explicit paths via `palace-commit --path` args. A concurrent session's uncommitted work was once swept into a STIGMERGY commit via `-A`. The `palace-commit.mjs` tool enforces this.
2. **Commit each phase the moment its gate is green.** Don't let working-tree edits sit while anything else might write.
3. **Clear stale locks before committing:** `rm -f .git/index.lock .git/HEAD.lock`. The `palace-commit` tool does this for you.
4. **The actuator must never fire a real `claude` during build/test.** It is stub-gated. Tests inject a `buildArgv` that runs `tests/fixtures/stub-worker.mjs`. The dev server fires the stub only when `STIGMERGY_STUB_WORKER=1`. `GET /api/worker` reports `stubbed`. Fire-through e2e/captures HARD-GATE on `stubbed`.
5. **Gate → vision-validate → commit, in that order.** Don't commit a failing gate; don't skip the visual check on a phase that has captures.
6. **The dev server:** `cd _ops/stigmergy/app && STIGMERGY_STUB_WORKER=1 npx vite --port 5173`. Playwright reuses it (`reuseExistingServer`).
7. **Node v25 cannot `node --check` a `.jsx` file** (`ERR_UNKNOWN_FILE_EXTENSION`) — that is NOT a syntax error. Validate JSX via vitest/vite; `node --check` only plain `.js`.
8. **Small sequential tool groups beat big batches.** Re-establish ground truth (`git status`, `ls`, grep) after any interruption.
9. **Show before write for canon.** CLAUDE.md, SCHEMA.md, README, SUBSTRATE, JEWEL, ROSETTA, FOUR PILLARS, `_ops/Substrate Skill.md`, `_ops/Palace Ceremonies.md`, individual `_ops/*Ceremony*.md` cards — these are hard-refused by STATE's editor allow-list (gate 17 spec) and must flow through Claude conversation under Loudon's eye.

## Honest gotchas + scars

- **Mermaid + lazy-load.** Mermaid is ~600KB and lazy-imported in `MermaidBlock.jsx`. The first entry with a `mermaid` fence pays the cost; subsequent renders are free. Don't make it eager.
- **The atomic-placeholder emphasis pipeline.** `EntryBody.jsx` and `lib/inline-prose.jsx` both tokenize code spans + wikilinks into `\x00<id>\x00` placeholders before running emphasis regexes. Adding a new "atomic" (inline math, embedded media) means extending the tokenizer pass; emphasis falls into place automatically.
- **URL nav: two hooks, one popstate listener.** `useEntryNavigation` (STATE) and `useCommitNavigation` (LOG) both register popstate listeners. They don't conflict — each only reads its own URL key. Adding `?<thing>=` for a third surface (QUEUE? Topology Lens?) follows the same pattern.
- **Response wire format.** Asker-supplied a/b/c options write `{ granted, option_id, option_label, notes }`. Generic Grant/Deny write `{ granted, constraints | reason, notes? }`. Freetext custom-response writes `{ granted: true, constraints: <notes-text> }` (notes textarea IS the response). All three shapes match the existing persistent-blackboard pattern; agents reading the wire pick them up the same way.
- **The pillars-style preservation hint.** `detectArrayStyles(beforeText)` scans the on-disk YAML for inline-vs-block array style and threads hints into the emitter so a stage edit doesn't restyle the pillars block. If you add a new top-level array field, add it to the detection scan or the emitter will pick the default style.
- **Audio plays open the native app via `/api/open`.** PhosphorAudio's `↗` chip uses the same endpoint as ArtifactSlot's open-external chip. Don't duplicate the endpoint — extend it if a new artifact type needs different open behavior.
- **`board: TRICKSTER` jump chip is hidden** for resource_request items because the pointer is the current deck. The chip stays for handoff_ready entry pointers. Don't re-add it to resource_requests.
