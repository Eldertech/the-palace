## The locked design (this is the spec — do not re-derive; Loudon tuned every beat)

**Reading order, top → bottom (context loads first; the question sits directly on its buttons):**
1. **who** — `[[Project Name]]` (cyan link). A quiet amber "waiting on you" **only when blocking**. No request-id, no `DOING` badge in the primary view.
2. **orientation** (the steward's *catchup* / "ground") — right under the name, dim. Where the project is / what it's doing. Must orient enough that the question's terms (e.g. "stage 2") are already understood by the time you read them. **Visible by default** ("we should see the catchup most of the time"). When a steward wrote no catchup, fall back to its raw note — **no pill**.
3. **evidence** (dynamic — only if present) — the audio to audition / pictures / schematic. Visible (perceiving it is part of the decision).
4. **the question** (the ask) — bright/prominent, sits **directly above the options**, nothing between them. *Context goes above the question; the question is adjacent to its buttons so a label like "approve stage 2" is legible.* This was the key fix — the ask used to float above the catchup, forcing the eye to jump.
5. **options** — **natural order, never reordered** (yes before no). The steward's recommendation is **marked on its own button** (brighter text/border + a small dim `rec`), **never a separate yellow lean panel**.
6. **▸more** = the deep *why* (rationale). **▸details** (nested) = the wire facts (ts · resource · health · id). Collapsed.

**Interaction — TWO STEP (anti-misclick; Loudon's explicit choice over one-click):**
- Click an option → it becomes **selected** (filled) → a "how to execute" row appears: `<label> — how?  [File]  [File & Run]  cancel`.
- **File** = record the answer (post the grant, `buildCardGrant` → `postMessage`). **File & Run** = record **and** advance that steward one cycle (`advanceSteward(item.from)`). **cancel** = back out. **No commit on the first click.**

**Radical minimalism (Loudon: "fewest words, icons, indicators, be dynamic, just show what is absolutely necessary"):** CUT from today's card — the request-id, the PARKED/DOING Tag (→ quiet "waiting" only when blocking), the "steward emitted no catchup" pill, every field label, the freeform-note label + hint, the separate `LeanPanel` (lean is now a button marking), the duplicated file buttons, and **all the repeated amber "steward leans →" panels** ("a ton of dramatic yellow writing repeated down the page"). Render only slots that have content.

**Then carry the same spine** to `src/components/queue/QueueItem.jsx` (proposal/flag/handoff cards) and `src/components/DigestPanel.jsx` rows.

## Receiving surface + gotchas (READ — the palace bit me here)
- **Shared single-worktree, N-writer repo.** HEAD thrashes — concurrent steward/orchestrator/other-session commits land on whatever branch HEAD points to. **Commit directly to `main`; do NOT create a feature branch in the shared tree** (branching hijacks their commits and diverges main — I learned this the hard way and had to merge back). Better still: **make your own worktree first** — `node _ops/worktree/new-worktree.mjs --name feature/trickster-redesign --profile stigmergy --memory` — then branch freely there. See memories `feedback_create_worktree_first` + `feedback_shared_worktree_branch_switch`.
- **Verify `git branch --show-current` before AND after every commit.** Stage explicit pathspecs (the tree carries entangled in-flight BLUELINE/Shop work — never `git add -A`). Don't pass already-deleted pathspecs to `git add` (it aborts). Structured commit: `ops(stigmergy): <subject ≤72 chars>` + `Palace-Kind/Entry/Verify/Author` trailers + the `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>` line.
- **Verify SAFELY:** `npm --prefix _ops/stigmergy/app test` (vitest, ~1233 tests, fast, safe). For Playwright, run ONLY the touched-surface specs — the live `:5173` dev server is **non-stub and fires real `claude -p` steward cycles**; never run `stewards.spec` or the grant-firing e2e paths.
