# STIGMERGY — Equation Rendering Build Plan

The visual language is [[BBS Design System]] — STIGMERGY uses the phosphor
aesthetic, **not** Loudon Live. The build-contract pattern is
[[STIGMERGY — Weave Flag Item Type Build Plan]] (the most recent sibling) —
match its shape: phased, each phase self-verifiable, stop-report on failure,
Loudon absent during the run. The four rendered options live in this entry's
bundle (`equation-rendering-proposals-mockup.html`).

## The problem

Free-text message bodies flow through `<Linkify>` with `white-space: pre-wrap`
(`app/src/components/MessageList.jsx` ~L226), so any LaTeX — `$$…$$`, `$a_k$` —
prints as raw source. A structured `EquationBlock.jsx` already exists and
already encodes the house rule in its own comment: **no KaTeX / MathJax / CDN —
terminal-native monospace, dual-channel symbolic + worded.** The question was
never "how do we render math" but "how do we honor that rule while making prose
math land on the grid."

## The three moves

1. **Inline pass — ships first.** A small transform turns inline `$…$` into
   Unicode-prettified spans (`a_k` → aₖ, `z^{-k}` → z⁻ᵏ) inside flowing prose.
   Subscript/superscript via Unicode where it exists (₀–₉, ₖ ₙ ₚ; ⁻ ᵏ ⁿ), CSS
   `<sub>/<sup>` fallback otherwise. No engine, nothing leaves the grid. Kills
   ~80% of the ugliness with zero aesthetic risk.

2. **Option B — the grid engine.** A LaTeX-subset renderer (`\sum`, `\frac`,
   `^`, `_`, `\cdot`, `\,`) lays the symbolic line onto the character cell: a
   stacked Σ (limits above/below via small spans) and fraction bars drawn as
   CSS rules. Covers ~90% of DSP math; exotic constructs degrade to the
   fallback. This is the *engine* that draws Option C's symbolic line.

3. **Option C — the display format.** Extend the existing `EquationBlock`
   dual-channel convention. Each display equation renders, top to bottom:
   **symbolic line → where-key → worded line.** The symbolic line comes from the
   Option B engine; the where-key and worded line are author-supplied.

## What's decided (do not re-litigate)

- **Reject KaTeX (Option A).** Its proportional math-italic/serif fonts can be
  recolored but never gridded; it reads as a textbook in a CRT costume, adds
  ~280 KB, and breaks the no-CDN house rule. The mockup keeps it only to make
  the tradeoff concrete.
- **Order inside the C block is symbolic → where → worded.** The where-key sits
  directly below the equation, just above the worded version.
- **The worded line is author-time, not render-time.** It is a *writing
  standard*: equations going forward are written with a worded form. It is never
  generated by the renderer.
- **Past equations are corrected by a Weave task**, not at render time — past
  uses are called out and fixed; the engine stays dumb.
- **Inline ships independent of the display options.** It lands first and
  carries its own value.
- **Raw-TeX-in-a-labeled-panel is the graceful fallback** for anything the
  subset parser can't lay out.

## Build phases

- **Phase 1 — Inline pass.** Add an inline-math transform to the body render
  path (the `<Linkify>` site). `$…$` → prettified span. Guard a bare `$` (dollar
  amount) in prose against being eaten as math-open. Verify: the screenshot's
  paragraph renders `a_k`, `e[n]`, `z^{-k}` on-grid with glow intact.
- **Phase 2 — Grid engine (Option B).** Implement the LaTeX-subset → grid
  layout for `\sum`, `\frac`, `^`, `_`, `\cdot`, `\,`. Verify against the AR
  model and the all-pole transfer function in the mockup.
- **Phase 3 — Wire into EquationBlock (Option C).** Reorder the block to
  symbolic → where → worded; draw the symbolic line via the Phase 2 engine.
  Verify the dual-channel block matches the mockup's Option C panel.
- **Phase 4 — Fallback + tests.** Raw-TeX panel for unparseable input; unit
  tests for the subset grammar; snapshot the four mockup cases.

## Weave flags

- **The worded-form writing standard wants its own palace entry** — the
  one-word register for "the same equation said twice, symbols and names" — and
  a Weave should either create it or link to an existing standard (the memory
  `feedback_equations_with_words` is its current, un-palace-ified home). Once it
  exists, this build plan `enables`-links to it and the [[Weave Ceremony]] that
  backfills past equations points at it as the standard being applied.
