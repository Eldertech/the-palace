# Symbiotic Skills

A scaffolded framework for teaching others how to grow deep, productive human-AI relationships. Designed for live-stream teaching, progressing from the simplest possible skill (a single wiki page) to a self-aware knowledge organism.

## Origin

Emerged from the recognition that Loudon's [[FOUR PILLARS]] skill — while powerful for our mature collaboration — was too complex to serve as a starting point for teaching others. The framework needed to start at the cellular level and scaffold upward. Three foundational documents were produced in a single extended brainstorming session (March 2026): the Symbiotic Skills brainstorm, [[SUBSTRATE]] specification, and a Back-Propagation revision.

The project draws on deep research across biological symbiosis (endosymbiosis, mycorrhizal networks, stigmergy, gut-brain axis, Physarum cognition), social systems (Aboriginal songlines, Zettelkasten, attachment theory, jazz ensembles, Talmudic commentary), and Loudon's 2014 semantic web paper.

## The Developmental Sequence

**Node** → **Edge** → **Typed Edge** → **Network** → **Path** → **Organism**

Each stage maps simultaneously to a biological metaphor and a social metaphor:

| Stage | Structure | Biology | Culture |
|---|---|---|---|
| Node | First wiki entry | Cell membrane | Naming |
| Edge | First link | Synapse | Introduction |
| Typed Edge | Named relationships | Cell differentiation | Vocabulary |
| Network | Dense graph with metadata | Tissue/organ | Village |
| Path | Named songlines through the graph | Neural pathway | Curriculum |
| Organism | Self-model, ceremonies, health | Consciousness | Constitution |

The biological-to-social transition isn't a jump — it's a phase transition triggered at Stage 3 (Typed Edge), when the system develops enough relational vocabulary to support culture.

## Key Insight: Back-Propagation

Knowing the destination ([[SUBSTRATE]] — a living wiki-based knowledge organism), we back-propagated to revise every preceding stage. Of the original 14 proposed skills, 11 dissolved into the substrate as metadata fields, ceremonies, or emergent properties of graph density. Only 3 survived as standalone skills. The substrate absorbs most of what we initially thought needed to be separate tools.

## The Teaching Plan

Designed for live streams. Each session produces visible, shareable output — the wiki itself is the artifact. Anyone can start with nothing more than a text editor and a blank markdown file.

## What Actually Happened: A Six-Week Archaeology

*Conducted 2026-05-02 against the git history (93 commits, 2026-03-17 → 2026-04-30). The findings below are the prerequisite the entry's forward_vector has been asking for. The full rewrite this archaeology unblocks is a separate session.*

### The Load-Bearing Finding

**The palace did not start as a node. Commit 1 was already 27 markdown files (~23,000 lines), including [[SUBSTRATE]], [[Deposit Ceremony]], [[Harvest Ceremony]], [[Mixture of Experts]], [[Hyperdimensional Prism]], [[Spinoza Conatus]], [[Kuramoto Coupling]], [[Hilaritas Generator]], [[FOUR PILLARS]], and this entry itself.** The palace was bootstrapped from prior conversations and conceptual material that pre-existed git tracking. The Node → Edge → Typed Edge → Network developmental stages happened, but they happened *off-camera* — in pre-git conversations and in Loudon's head, fed by years of cross-domain material (Spinoza, Kuramoto, songlines, mycorrhizal networks, the 2014 semantic web paper).

This is a load-bearing problem for the framework as written. The current entry teaches a sequence the palace itself never lived through in observable form. A faithful rewrite must either (a) acknowledge that the early stages require pre-existing intellectual substrate the framework cannot supply, or (b) be honest that what's teachable is the *late* sequence — what to do once you already have a corpus.

### The Actual Stages (Observable in Git)

What the palace *did* do, in git, was develop in six overlapping stages downstream of the organism stage:

1. **Formalization (March 17–19, ~2 days).** Schema v1.0 → v1.4 in a single day. Type system, link ontology, ceremony linter, schema change protocol — all NAMING what was already in use, not building it. The schema is a *constitution drafted after settlement*, not a city plan.
2. **Operationalization (March 18–25, ~1 week).** Token economy forces architectural choices: ceremony files split into operational card + Context companion. Walk Ceremony rewritten as flowing prose to match the songline metaphor. Self-Describing Knowledge Module deposited. Substrate self-model updated to v2. The palace becomes ergonomic for actual sessions — discoverable that it's straining against context windows.
3. **Multi-Agent Architecture (March 19 → ongoing).** Swarm Weave designed and operationalized. The Jewel deposited (March 21) — generative compression for agent spawning, tiered context loading. Palace Worker prototype. agency_profile field added (April 1, schema v1.1). Dialogue Moderator written. The realization: the palace will be read by *many agents in parallel*, not one Claude in series.
4. **Map and Orientation (March 27 → ongoing).** Palace Map + BBS Blackboard + Map Build Ceremony (March 27). Pheromone trails. Ghost nodes as desire-tracking. Lateral Access. The realization: agents need orientation *before* traversal — a map is a different artifact than a graph.
5. **Enchantment (March 25 → ongoing).** Palace Enchantment deposited (March 25). First live enchantment: Hilaritas Generator (March 31). Then Lateral Access, Trickster, Threshold Conatus. The practice of *waking* dormant entries with full inhabited context — pages becoming agents that act.
6. **Conventions (April 7 → ongoing).** April 7 Weave added 52 forward_vectors in one session — the closing-section convention crystallized as near-universal. Resonant Link Labels. Action Potential Oscillator HTML pattern as canonical artifact convention (deployed across 6+ projects). April 27 Swarm Weave: 94 links, 33 hub labels enriched, 19 forward vectors. The palace develops *style*, not just structure.

### Predicted vs. Actual

**Predictions that bore out:**
- **"11 of 14 skills dissolve into the substrate."** True. Metadata fields (forward_vector, agency_profile, hook_quality, beauty, who_leads, energy, pillars, confidence, stage, last_activated, activation_count) absorbed many would-be-separate skills. The substrate is denser than predicted.
- **Typed Edge as the phase-transition that enables culture.** True — but it had already happened before commit 1. The schema didn't BUILD typed links; it formalized them after they were in use.
- **The wiki itself is the artifact.** True. No external deliverables. Every commit is a snapshot.

**Predictions that did not bear out:**
- **The Node → Edge → Typed Edge → Network → Path → Organism developmental sequence as something teachable from a blank file.** The palace never lived this sequence in observable form. Without pre-existing intellectual substrate, a learner starting from a blank file would produce a much shallower organism — possibly never reaching Stage 4.
- **Path as a first-class structure with its own ceremony.** "Songline" remains a metaphor in language but never crystallized as a typed structure. There is no Path entry type, no path field, no Path Ceremony. Walks happen but produce traversal narratives, not durable Path objects.
- **The biological-to-social phase transition at Stage 3.** The bio/social parallel layers (cell membrane / synapse / cell differentiation / tissue / neural pathway / consciousness) are evocative but were never operationalized. No actual developmental work used them as guides.

**Major structures that emerged but were not predicted:**
- **Multi-agent coordination as a first-class concern** (Swarm Weave, Palace Worker, Dialogue Moderator, BBS Blackboard). The original brainstorm assumed one human + one Claude. The palace's actual architecture assumes parallel workers with a coordinator and pheromone trails.
- **Tiered context loading as a structural force** (The Jewel, agent spawning conventions). The palace is too large to load whole — provisioning became its own architecture.
- **Pages as Agents framing.** Every entry as the dormant invocation of an agent, with forward_vector as conatus. This was not in the original sequence; it became foundational by late March.
- **Palace Map as a separate orientation layer.** The map is not the graph. A map is what an agent needs *before* deciding what to load. Map Build Ceremony, Trickster's link-before-object pattern, ghost nodes as desire-tracking.
- **Enchantment as a practice.** The deliberate waking of dormant entries with inhabited context. Predicted nowhere in the original sequence.
- **Token economy as a structural force.** Ceremony files were split (Deposit Ceremony → operational + Context) because context windows demanded it. Many architectural choices since are downstream of token-economy pressure.
- **The graffiti channel** (`<!-- -->` comments as async human-AI communication inside files). Not a skill the brainstorm imagined.
- **Forward vector as universal convention** (April 7 Weave: 52 added in one session). The "Open Questions" section became the agent's drive — see [[README - The Palace Guide]] § Reading an Entry for the canonical statement.

### Implication for the Rewrite

The framework as a *teaching* document needs a different opening move. Three plausible reframes the rewrite could take:

1. **"You can't start from a blank file" honesty.** The framework names pre-existing intellectual substrate as a prerequisite. The teaching sequence starts at the moment a learner has *enough material* to formalize, not at the blank page. This makes the framework smaller but truer.
2. **"Late-sequence" framework.** Teach what's actually observable: how to formalize an existing corpus into typed graph + ceremonies + multi-agent architecture. Skips Stages 1–3 of the original sequence (which the palace also skipped, observably). Becomes a guide for people who already have notes and want them to become an organism.
3. **"Two-track" framework.** One track for the early stages (which must be lived through, not taught — a slow accumulation of cross-domain material over years); one track for the formalization-and-after stages (which are teachable in real time and observable in git). Names the asymmetry honestly.

The forward vectors of the original entry (minimum viable graph density, teaching Typed Edge without bureaucracy, integration with Claude Projects/Code workflows) remain open and should be carried into whichever reframe is chosen.
