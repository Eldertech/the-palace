# Weaving Memory into the Palace

![[Weaving Memory into the Palace — hero.png]]

An operator (Claude Code) keeps a small, auto-loaded working memory — facts about how to run safely in this repo, notes on in-flight work, hard-won gotchas. Left alone, that memory **silently drifts from the palace**: a branch it tracked gets merged, a path it names moves, a lesson it holds gets written into a Shop entry. What began as a helpful note becomes a **stale, rival source of truth** — the one thing the palace is built never to have.

This practice is the cure, run as a sweep: audit the whole memory against the palace, and move every durable thing home. The palace is the source of truth; memory becomes the thin **trigger layer** that fires the rules which must act *before* you would think to open a palace doc.

## The procedure

**1 · Audit every memory against the palace.** Read each memory and find where its content already lives — or should live — in the palace. The palace wins every conflict.

**2 · Give each memory one of four dispositions:**

- **Remove** — the content is fully in the palace (or superseded). Delete it. (Verify first: a memory that *claims* "already captured" often isn't — check the named palace doc actually holds it.)
- **Align** — the memory drifted from current truth (a branch it called "unmerged" has merged; a path moved). Fix it to match reality.
- **Repoint** — the memory restates palace content and could drift. Shrink it to a careful pointer at the palace doc, keeping only the always-on trigger.
- **Place → remove** — the durable content exists *only* in memory. Write it into the right palace doc **first**, then delete the memory. Nothing is lost because the palace held it before the memory left.

**3 · Fix pointer integrity.** After deletions, no memory may dangle a link to a deleted sibling. Every survivor either points to its palace source of truth, or is honestly labelled **operator-env native** — a Claude Code / OS fact (usage limits, model tiers, `open -R`) the palace has no reason to hold, and therefore nothing it can drift from.

**4 · Consolidate near-duplicates** into one memory that keeps each trigger and points once to the palace (e.g. a cluster of git/worktree cautions → a single "shared-tree discipline" nugget → [[Worktree Practice]]).

**5 · Land in the well-defined end state.** Memory now holds *only* the **always-on operator floor** — the rules that must fire proactively, since `MEMORY.md` is the only auto-loaded operator surface (the palace's auto-loaded tier, Tier 0–2, is knowledge, not operating instructions). Everything else is in the palace, discoverable on demand. Memory is the trigger; the palace is the truth.

## Why it belongs to the Weave

The [[Deposit Ceremony]] plants new tissue; the [[Weave Ceremony]] tends what exists and fixes what is mis-located or mis-linked. Operator memory is exactly a mis-located, mis-linked body of knowledge that accretes between Weaves — so the sweep is a natural Weave sub-step, run each cycle on the same cadence that catches unsung paths and stale links. It [[deepens]] [[Palace as Context Injection System]]: the palace stays a clean context-injection surface only if the *other* always-loaded surface — memory — is kept from quietly contradicting it. And it [[couples-with]] [[Closing Well]] — a memory reduced to an honest pointer is the same honesty as a handoff that names what it couldn't verify.

The first run (2026-07-03) took operator memory from **45 files to 6**, every removed piece verified into the palace first.
