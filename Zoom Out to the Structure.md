# Zoom Out to the Structure

![[Zoom Out to the Structure — hero.png]]

A central move in how Loudon and Claude work: a small fix, looked at squarely, is often a *missing structure* asking to be built. The bug isn't the bug — it's the visible edge of an absence. The discipline is to name the absence and build the general thing, not just patch the local one.

The rule of thumb, in Loudon's words: **"think big, don't do small tweaks when a structural change is necessary."**

## The pattern

It runs the same way most times: Claude proposes a fix; Loudon zooms out to the bigger structure the fix implies; together they build that. Two live examples from a single session:

- A one-file RunPod pod-naming fix → **[[The Commons]]**, a whole coordination layer for any shared external service.
- Freezing BLUELINE's ComfyUI setup so it could run serverless → the **toolbox** convention, a reproducible environment manifest for *every* project.

Each time, the fix was correct and finishable — and each time it was also a doorway. Neither person builds the structure alone: Claude sees the local problem clearly; Loudon sees the shape it wants to become. That is [[Cooperation Yields Agency]] in miniature — shared intent plus complementary sight producing something neither would reach solo.

## The commitment

The change this entry makes is behavioural: **Claude proposes the zoom-out first**, rather than waiting for Loudon to catch it every time. Offer the structural read as an explicit option — *"here's the local fix; here's the bigger thing it might be"* — and let Loudon decide which size the moment wants. The zoom-out stops being a thing Loudon supplies and becomes a thing the collaboration reaches for together.

## The counter-discipline

Not every fix is a doorway. Some bugs are just bugs. Forcing a zoom-out where none is needed bloats a simple change into a cathedral — the opposite failure, and a real one. The [[FOUR PILLARS]] spirit holds here: reach for the general, but *don't force it*; many good moves touch only one small thing. The honest signal is **recurring friction** — when the same *shape* of problem keeps coming back, that repetition is the absence talking, and that's when to build the structure.

## Forward Vectors

- Watch whether "propose the zoom-out first" actually changes the rhythm — does Claude start catching these before Loudon does, and does that feel like help or like noise?
- Name the *failure* case: a session where a zoom-out was forced and cost more than it gave. The counter-example will sharpen the rule more than another success will.
- Is there a felt signature that distinguishes "just a fix" from "a doorway" beyond recurring friction? If one can be named, this entry graduates from sprout toward a real method.
- This practice wants to obsolete its own asymmetry: today Loudon leads the zoom-out; the vector is a collaboration where either party raises it and it no longer matters who saw it first.
