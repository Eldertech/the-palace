# BLUELINE M3.5 — the whiteness-preserving noise warp (report)

**Date:** 2026-06-19 · Mac-side Claude Code (feature/blueline-m3 worktree) · follows [m3-report.md](m3-report.md).
**Question (two parts):** (1) M3's flow-warped render collapsed to rainbow garbage — was that a *method* bug,
and can the correct noise-warp fix it? (2) With a correct warp, does flow-warped noise now **beat seed-lock**
at the 482 px delta?

## The fix — forward-splat + L2-normalize + hole-fill (HIWYN / Go-with-the-Flow core)

M3 used a backward-warp + *global* renormalize. That holds mean/std but not **spatial whiteness**: in
expansion/disocclusion regions a backward warp pulls many destination cells from the same few sources →
correlated blocks → the diffusion prior reads them as off-manifold → rainbow striping. `warp_noise_gtf.py`
does it the published way:

- **Forward-splat** each source noise cell to where the flow sends it.
- **Normalize each destination by the L2 norm of its weights** — `out = Σ(w·z) / √(Σ w²)` — not the L1
  bilinear average. `Σ w·z` of independent unit Gaussians has variance `Σ w²`, so `/√(Σ w²)` gives
  **exactly unit variance per cell** (the whiteness trick; an L1 average shrinks + correlates variance,
  which a global renorm can't undo).
- **Fill disocclusion holes** (cells no source landed in — the expansion case) with **fresh** N(0,1).
- **Nearest-neighbour splat** (each source → one cell) so adjacent destinations share no source.

**Whiteness diagnostic** (lag-1 spatial autocorrelation; white ≈ 0):

| noise | lag-1 autocorr |
|---|---|
| base `N_A` (white) | +0.001 |
| M3 naive warp (rainbow) | **+0.127** |
| GtF bilinear splat | +0.069 |
| **GtF nearest splat** (shipped) | **+0.001** |

Nearest-splat warped noise is **as white as the base noise**, yet has *moved* with the motion (0.86 mean-abs
from `N_A`; 66 % warp-filled, 34 % fresh). **Local SDXL gate (free):** same pose A + prompt as M3's rainbow
`NW.png`, but the GtF-warped noise renders a **coherent figure** (`local-sdxl/NW_gtf.png`) whose composition
echoes the `N_A` anchor. **Part 1: yes — it was a method bug, and it is fixed.**

## Pod re-test — coherent, and now ~level with seed-lock ❌ (but not garbage)

Same 482 px pair, same prompt/params, FLUX-ControlNet on a RunPod 4090. A / B-seed-lock / B-warped-**gtf**:

| pair | `embed_cos` | `color_corr` |
|---|---|---|
| A vs B · seed-lock | **0.744** | **0.380** |
| A vs B · warped (naive, M3) | 0.508 | 0.016 |
| **A vs B · warped (GtF, M3.5)** | **0.709** | **0.373** |
| delta (GtF − seed-lock) | −0.035 | −0.007 |

The fix vaulted the warped render from **incoherent garbage (0.508/0.016)** to a **coherent, palette-matched
figure essentially level with seed-lock (0.709/0.373 vs 0.744/0.380)** — `renders-gtf/B_warped_gtf.png` is a
real, on-brief B frame (fur-collared coat, leap pose, moonlit mist), not a rainbow. But it **does not beat
seed-lock** at this delta: the two are a statistical tie, the warp marginally *below*.

**Read:** at a **482 px single jump** — coil crouch → full leap, ~34 % of the latent disoccluded — warping the
noise neither helps nor hurts versus simply reusing it. Both land at ~0.71–0.74 / ~0.37. That is the expected
shape: [[Go-with-the-Flow]]'s gain is across **small incremental** motion (video frames), where most of the
field is *transported* (little disocclusion) and the moved structure still carries identity. One giant staged
jump is past that regime — the shared latent (seed-lock) is just as good an anchor as a heavily-disoccluded
warp.

## What M3 + M3.5 together establish

1. **M3's negative was half implementation.** The naive warp broke the white-noise prior; the correct
   forward-splat / L2-norm / hole-fill warp produces coherent renders (the rainbow is gone).
2. **At an extreme delta, warped noise ties seed-lock** — it doesn't beat it. The thesis "warp beats
   seed-lock" is **unconfirmed at large delta**, and the data says large-delta is the wrong place to test it.
3. **The real test is small-delta / incremental** (M3.6): a short pose increment, or a multi-step walk along
   the clock, where transport dominates and disocclusion is small. That is [[The Flow Field is the Spine]]'s
   actual operating regime — moving the noise *frame-to-frame along the song*, not across comic-panel cuts.
4. **Design conclusion for BLUELINE:** between comic panels (large staged jumps) the coherence levers are
   seed-lock + identity + depth + img2img; *within* a motion (small increments) the flow-field spine can move
   the noise. The spine is a within-shot tool, not a between-shot one.
